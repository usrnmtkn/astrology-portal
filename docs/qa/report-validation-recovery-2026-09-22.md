# Generated report validation recovery

## Changes

- Friends fact validation accepts explicitly supplied relationship activations in a bounded relationship paragraph. It distinguishes the reader's natal point from the friend's personal transit. A paragraph break or a return to third-person personal material ends second-person context.
- Judge diagnostics quote exact reader-visible text and, when cited, an exact passage at a JSON pointer in the governed brief. Contradictory perfect scores, fabricated quotations, and unexplained below-floor scores are rejected as invalid diagnostics. Existing release floors and blocking findings remain in force.
- Judge adapter v1.6 supplies the complete v3.1–v3.4 report rubric instead of only the final amendment. The generic card reviewer prefix is removed. Approved source documents remain byte-identical; only their premium response-format sections are omitted from the assembled short-report packet, which has one scores/findings output contract. The adapter maps packet fields, category aliases, fixed headline metadata, and short-report paragraph applicability explicitly.
- Every general owner-voice objection must identify an eligible supplied comparison passage, quote it exactly, and explain the observed difference. Missing, invented, or duplicated comparison citations fail diagnostic validation before a correction writer runs. Validated comparisons reach the bounded correction and cleanup prompts. These checks establish citation integrity, not the editorial truth of the criticism.
- The short-report writer and judge schemas are included in the real provider-schema compiler regression. Nonempty quotations use its supported string pattern and remain independently enforced by diagnostic validation.
- Short-report date validation recognizes full and abbreviated month names and explicit endpoints such as “Sep 10–30.” It still rejects unsupplied interior dates, month swaps, and dates assembled across unrelated fields.
- Revisions receive quoted diagnostic evidence and retain unaffected wording. The existing bounded writer/correction/cleanup/review sequence is unchanged.
- Every writer attempt receives language policy from the same constants and generated policy data used by validation, including contextual exceptions and advisory classes. This prevents undisclosed unconditional bans from consuming correction calls. Quality revisions address diagnosed abstract scaffolding rather than replacing it with synonyms; deterministic cleanup remains restricted to its specific findings.
- Daily report submission waits for source loading and rebuilds the brief from the governed renderer after the current publication overlay is installed. It cannot submit the earlier brief after a loading exception or account change.
- Retry and worker-yield transitions persist a waiting state. Terminal report failures say “Could not finish”; the reader is not asked to perform an internal review.
