# Generated report validation recovery

## Changes

- Friends fact validation accepts explicitly supplied relationship activations in a bounded relationship paragraph. It distinguishes the reader's natal point from the friend's personal transit. A paragraph break or a return to third-person personal material ends second-person context.
- Judge diagnostics quote exact reader-visible text and, when cited, an exact passage at a JSON pointer in the governed brief. Contradictory perfect scores, fabricated quotations, and unexplained below-floor scores are rejected as invalid diagnostics. Existing release floors and blocking findings remain in force.
- Revisions receive quoted diagnostic evidence and retain unaffected wording. The existing bounded writer/correction/cleanup/review sequence is unchanged.
- Daily report submission waits for source loading and rebuilds the brief from the governed renderer after the current publication overlay is installed. It cannot submit the earlier brief after a loading exception or account change.
- Retry and worker-yield transitions persist a waiting state. Terminal report failures say “Could not finish”; the reader is not asked to perform an internal review.

## Evidence and validation

Saved failure material remains outside Git. A local replay of the exact supplied relationship activation that previously failed now passes without modifying that passage. Public regression fixtures are synthetic.

The publication/source regression reproduces the distinction between a withheld unversioned bundle and its eligible current published passage, then verifies recovery of the full opening and ending before report assembly. This proves the loading failure mechanism; it does not establish the complete timing history of a past browser session.

Local checks cover relationship ownership and context, judge diagnostic integrity, 45 delivery cases, 27 reader-contract cases, checkpoint replay and budget bounds, targeted corrections, source handoff, and source preparation. The mandatory Content Studio API suite, API/web typechecks, CSS audit, and privacy scan are required before review. Browser checks exercise real report list labels in both themes and viewport sizes, and source loading, retry, and sign-out behavior at the report request boundary.

## Remaining release evidence

No live provider calibration is claimed by these deterministic tests. Judge protocol compliance and writing quality still require a separately authorized, cost-bounded daily, weekly, and Friends verification. Each report must use the production generation path, pass independent review, save completely, and retain its opening and ending when retrieved by the app.

Keep historical checkpoints immutable. Changed prompts/schema require a fresh reviewed run, not a reset or replay under incompatible instructions. Do not mark existing failed reports complete. Do not lower thresholds or add paid retries to obtain a passing result.
