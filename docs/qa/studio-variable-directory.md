# Content Studio variable directory

The Variables navigation item opens `#variables`. Search covers token names,
meanings, providers, source keys, and usage contexts. Type and Used in dropdowns
combine with the search; Clear filters restores the full directory.

The directory is generated by `scripts/build-studio-variable-catalog.mts` during
the existing Studio metadata build. It consumes the placement fact contracts,
Writing Library and ingress registries, serving package template dependencies,
Daily Sky Summary allowed slots, and CMS surface starter contracts. No reader
copy, variable acceptance contract, or publication behavior is changed.

Identical names with different providers retain their separate definitions.
Daily Sky Summary keeps single braces. Ingress-only facts such as passEntryDate
are listed for compositions, not Placement articles. Undocumented providers
have an explicit filter and do not offer an editing action. Custom placement
sources in the serving package are included under their placement context.

Editable definitions list their exact source keys and fields. Choosing a source
opens the existing fully hydrated editor. Saving, review, publication, conflict
checks, and source hash protection use that editor's existing contract. Closing
it returns to the same search and filters. Shared zodiac season definitions
point to their twelve sign sources; placement phrases point to their placement
Writing Library fields. The catalog contains metadata, not current prose values.

The page and its metadata load only on demand. Usage lists and search results
are paginated. Metadata deduplicates repeated context/source records in the
transport. Styling uses the existing canonical Studio components and stylesheet.
The 2.4 kB gzip page chunk requires a 3 kB aggregate JavaScript allowance in each app; all
startup, CSS, reader and individual deferred chunk caps remain unchanged.

Validation commands:

- `npm run test:studio-variables`
- `npm run test:content-studio-api` (full unfiltered suite)
- `npm run qa:css-audit`
- `npm run build:admin` and `node scripts/check-admin-bundle-budgets.mjs`
- Web build with the CI fixture environment and `npm run qa:bundle`
- `npx playwright test --config=playwright.studio-variables.config.ts`
- After the merged main deployment is Ready, repeat the browser command with
  `STUDIO_PRODUCTION_ENTRY=1 PLAYWRIGHT_BASE_URL=https://tldrastro.vercel.app`.

The browser tests use the actual content API handler with isolated synthetic
storage. They never write test prose to production. Coverage includes mobile
and desktop, light and dark, populated and empty results, combined filters,
clipboard syntax, source draft save/reopen, returning to filters, heading
consistency with the existing Templates page, placement-specific phrase editing,
unsaved draft protection, deferred loading, retry after metadata failure, and page errors.

The September 15 design follow-up verifies 24px between cards, 24px desktop and
16px mobile insets, and stable categorical token colors with at least 4.5:1
contrast. Controls and cards reuse the canonical Studio surfaces, grids and
headers. Browser screenshots cover both themes and screen sizes.
