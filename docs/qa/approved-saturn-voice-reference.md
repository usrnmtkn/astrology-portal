# Approved Saturn voice reference

The owner requested saving the complete Saturn in Aries passage as an approved
voice reference and using its style for future horoscopes and write-ups while
keeping existing writing rules. The exact source and scoped approval are in
`data/writing/approved-voice-style/saturn-aries-20261020.json`.

The passage is assistant-written and owner-approved for style use. It is not
owner-authored, a current chart, or approved reader-serving content. Its 196-word
body has SHA-256
`bd9e64d07024c4899150056265b4f7a22afd074a4c9eb94b1b126319d6994fca`.
The earlier comparison drafts are not promoted into positive voice evidence.

## Application

The complete passage enters actual writer inputs as a distinct
`OWNER-APPROVED STYLE REFERENCE`. Existing author passages, explicit corrections,
saved Studio profiles, target register, output formats and factual boundaries
retain their roles. The reference supplies ordinary language and connected human
reasoning. Its Saturn facts, responsibility scenario, paragraph count and advice
are not templates for other readings. Enjoyment and other emotional ranges remain
available when supported by the target astrology.

Daily, Weekly, Monthly and Seasonal prose requests receive the reference. Lunar
writing and the shared article/natal prose and template-slot routes receive it
within their existing workflows. Sky placement and aspect writers receive it
without adding calls. Dedicated Personal Transit and relationship projections
retain their current primary voice workflow. Existing report payload writers do
not acquire the new source through the shared prompt's early-return boundaries.

Source and exact-text hashes identify the new reference separately from the
owner-authored corpus and neutral Hellenistic meaning. Horoscope and lunar plans
bind its source hash. Seasonal requests pin the complete reference; rebuilding an
older request that lacks this source does not add it. Existing Seasonal voice
review sees the pinned style reference, while meaning review retains its factual
scope. No review stage, provider routing or paid-call budget is added.

The generic ghostwriting skill is not shipped into the app as a competing rule
set. Its marketing frameworks, quotable-line techniques and blanket removal of
conditional language do not override the owner's rules. The explicitly selected
passage is the style evidence.

## Verification

- `npm run test:approved-voice-style` verifies the complete exact passage,
  authorship, scoped approval, hashes, corruption rejection and source boundaries.
- `scripts/test-horoscope-latest-instructions.mts` inspects actual writer inputs
  for all four periods and preserves current profiles, saved copy and running
  requests.
- `scripts/test-seasonal-composition.mts` checks whole-source delivery, pinned
  review context, legacy request preservation and unchanged call counts.
- `scripts/test-transit-ingress-meaning-delivery.mts` intercepts the actual
  provider transport for both slot providers and the shared article writer.
- The full Content Studio API gate, server types, fresh production-entry browser
  profile journey, browser knowledge boundary and privacy checks remain release
  requirements. Current results belong to the release receipt and PR checks.

Generation checks use isolated storage and synthetic provider responses. They
verify source delivery and preservation, not the quality of new model prose.
No existing reader copy, saved profile, publication state or calculation setting
is changed by this integration. Future drafts still require their own review and
exact wording approval.
