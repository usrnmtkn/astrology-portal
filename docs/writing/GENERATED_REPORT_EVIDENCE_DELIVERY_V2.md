## Delivery decision

One combined reviewer evaluates the complete report. All nine scores and the
old strict verdict remain diagnostic audit data. No score, aggregate threshold,
general voice mismatch, preferred ending, or repetition category alone blocks
delivery or triggers rewriting. Writing quality remains a separate release
acceptance decision on complete real reports.

The judge's proposed blockers have three finite kinds:

| Kind | Required evidence |
| --- | --- |
| Source contradiction | Exact claim within the quoted draft passage, claim type, selected locked-source path and specific contradiction |
| Unsupported claim | Exact added claim, its assertion/prediction/illustration/interpretation/advice type, relevant source or explicit absence of support, and the precise unsupported addition |
| Explicit owner rule | Exact candidate construction, a registered contextual rule, complete original rule and hash, and an explanation of applicability and exceptions |

An ordinary conditional illustration can develop a source's meaning within its
domain without reproducing the source's exact words. Conditional language does
not license invented events, outcomes, durations, certainty or biography.
Editorial dissatisfaction cannot establish a factual gap. A category label is
not proof: even `unsupported_timing` is advisory without admissible claim
evidence. Conversely, an evidenced factual defect blocks despite perfect scores.

Owner-language review uses a deliberately finite registry of the contextual
asking-for-attention construction, three specified vague-real constructions,
and the redundant settled/stable pair. It carries each complete original
instruction. The registry's candidate matches cannot extend to all uses of
asking, real, or stable. Literal exceptions still require semantic assessment.
Other factual owner directions use source comparison. Other editorial wording
observations remain advisory. Existing deterministic explicit bans, fact locks,
subject/register checks, placeholders, required fields and length bounds stay
in force; this change does not replace the shared writing validator.

Runtime verifies exact quotations, source identity, allowed claim types and
rule identities. It does **not** prove that a model's semantic explanation is
correct. A model can miss a defect or misstate its significance. Frozen
calibration must check both false rejections and false acceptance.

## Prompt, correction and persistence

The candidate uses a separate prompt and response schema. It does not concatenate
the historical numerical release instructions and then try to override them.
Owner comparison retrieval remains unchanged. Each finding carries nullable
delivery evidence. Missing candidate evidence is not inferred from an archived
review. Historical verdicts and source documents are not rewritten.

Only supported blocking findings enter the one judge-directed correction.
Advisory findings are retained in the audit. A corrected draft that fails
deterministic validation is held immediately under this policy; there is no
additional paid cleanup. One final combined review reconciles the prior findings.
Unresolved defects, malformed review or a failed corrective call stop this cycle.
The existing initial deterministic recovery budget remains bounded (at most
three writer attempts before the first judge), giving a maximum of six calls
for a full report: four writer calls and two judge calls.
Initial recovery exhaustion and initial writer/reviewer failures also stop the
candidate job rather than starting a new attempt. A checkpoint yield resumes
the existing attempt without dispatching completed steps again. A failure before
a complete draft exists records the reason without inventing a draft hash.
The candidate disables provider fallback and caps complete request bytes at
87,808, writer output at 12,000 tokens and reviewer output at 6,000 tokens.
Oversized requests stop before dispatch; no source is clipped to meet the cap.
These caps apply in the hosted path too, not only in a local test wrapper.

Checkpoints include the exact policy in request identity. Changed policy cannot
reuse old provider checkpoints. Saved successful results keep the original
strict verdict, scores, blocking/advisory findings, policy, draft hash and
reconciliation. A candidate delivery pass is not an owner prose approval.
Holds retain drafts in protected checkpoints, job/entitlement and failure reason.
Neither cron nor user re-request restarts a completed quality cycle.

## Acceptance and activation

1. Run synthetic protocol and full lifecycle tests, including low-score delivery,
   actual factual blockers, malformed judgments, source/rule scope, exhausted
   corrections, persistence, retrieval and rollback. These are code tests, not
   evidence of semantic model accuracy.
2. Preserve unmodified archived responses and replay their original policy.
   They are development evidence; never call them held-out cases or retroactively
   assign this policy's fields to them.
3. Assemble nine complete report-shaped controls: three report types, each with
   supported source-copy content, an injected contradiction, and an unsupported
   factual claim. Preserve whole source strings and keep injected faults only
   in private non-serving fixtures. Label against the complete source before
   seeing model results. These controls use familiar source snapshots and are
   not independently authored or held-out natural reports. Freeze code, sources, requests and labels
   before dispatch. Run each twice (18 judge calls). Require both acceptable
   judgments to allow delivery and both negative judgments to identify the
   specific labeled defect. Every unresolved disagreement, missed defect,
   unsupported rejection or invalid response fails the candidate. Bad style
   alone is not a negative delivery label.
4. Reserve the entire remaining validation program before requesting an API
   extension. The recorded remaining allowance is 13 calls and $2.115044 of the
   aggregate $5 cap; calibration alone needs 18 calls. No new paid run is
   authorized by successful offline tests.
5. After calibration passes, verify real Daily, Weekly and Friends generation,
   saved bodies, complete reader rendering and reload, with separate review of
   the writing. A held or weak report fails that pilot; do not silently tune the
   same cases and call the rerun independent validation.
6. Required exact-head CI, privacy checks and fresh browser verification precede
   merge. Enable only the verified policy through the normal main deployment.
   A live claim additionally requires authenticated new generation, persistence
   and reader retrieval on the deployed revision, with reserved production calls.

The repairing agent owns pilot-hold investigation. A standing production hold
operator and recovery procedure must be assigned before activation; unattended
Needs review is not successful fulfillment. Rollback selects `strict` for new
runs and does not clear holds or rewrite completed reports. Do not bulk reset
jobs, erase billing history, fabricate ready bodies or require another purchase.

Nine cases twice are a bounded acceptance check, not an estimate of the general
failure rate. A failed candidate is rejected. Any later candidate needs an
explicit explanation of the failed criterion and fresh evaluation evidence.

The controlled set replaces the earlier plan's unspecified independent set;
that stronger evidence is not available and must not be claimed. The subsequent
fresh complete-report check remains required, with every proposed blocker
manually checked against its source and every complete report assessed for
writing quality. Passing obvious fault injections alone cannot authorize release.
