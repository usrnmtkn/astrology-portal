Local repair based on main `262dcd9570024715950aaa803b2a5521d62a1a64`,
branch `codex/ingress-full-request-repair-20261022`. This is an instruction and
source-delivery repair, not evidence of improved generated prose or deployment.

## Confirmed assembly defect

The dated system qualified the useful-next-move rule as optional. Article memory
independently rendered the generic article version and appended a second rules
bundle. A regression through the actual handler reproduced two bundles before
the repair. The earlier tests checked the system qualification and retired
structure separately, missing the later contradiction.

Current dated ingress memory delivers the same complete scoped corrections and
their provenance, without rendering another effective-rules bundle. The provider
system remains the sole location of those rules. Other article memory retains
its prior behavior. Live correction retrieval, scope, integrity, conflict and
unavailable-store checks are unchanged.

## Editorial and evidence changes

`INGRESS_WRITER_CONTRACT` v5 owns the system authority, task, field descriptions,
opening and craft direction, factual-claim limits, voice-reference wrapper and
default owner direction. The wrapper no longer independently tells the writer
to preserve the historical saved template's structure over the current contract.

The opening establishes the dated event while developing the season's human
meaning. Sign, planet and dignity details explain that thought when useful.
Hemisphere and equinox cautions remain factual claim boundaries, explicitly not
an assigned introduction or disclaimer paragraph. The final comparison asks if
the astrology explains a recognizable reason, rather than adding a definition,
example and abstract conclusion. No fixed paragraph sequence or hook quota is
introduced. Custom owner direction remains intact; requests without notes
receive the current ingress correction instead of a generic reference reminder.

The complete calculation plan remains unchanged for validation and inspection.
The writer projection removes duplicate position-display strings and app-owned
date-bullet strings, retaining the same complete event objects. Dignity basis is
delivered once rather than repeated for each participant. Every selected meaning
source remains complete and unchanged. The receipt hashes this projection as
`ingress-writer-evidence/v1` in addition to the full plan and source hashes.

Complete KB, learning-axis, Calendar, collective event and original owner sources
remain distinct from voice evidence. The complete private Libra benchmark and
Scorpio reference retain their exact hashes, authorship and voice-only scope.
The app still supplies calculated title, When and all Key dates. Requested prose
fields, model settings, selected events, factual validators, one-call behavior,
authorization and owner approval boundaries are unchanged.
