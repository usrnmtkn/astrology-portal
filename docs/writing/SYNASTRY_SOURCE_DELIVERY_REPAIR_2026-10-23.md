# Synastry source delivery repair

This change addresses sources and request assembly for directional Synastry
writing. It does not establish a successful voice evaluation, owner approval of
new prose, or a production deployment. The previously generated samples remain
rejected or held under their existing decisions.

## Source defects and changes

The neutral draft knowledge combined interpretation with reader instructions.
The Sun–Moon trine's `plainTranslation`, for example, ended with an instruction
to prevent comfort becoming autopilot. Removing the separate `advice` field
did not remove that instruction. Its supplemental `tension` also supplied a
general maintenance warning to an otherwise supportive reading.

The source repair moves complete trailing advice sentences from 87 neutral
draft entries into their existing `advice` fields, preserving their exact
wording. Four supportive Sun–Moon records also move their complete maintenance
cautions there, including the two corresponding failure-mode clauses. In total,
88 records change and 93 text units are separated. No approved reader row,
complete owner passage, book source, or approved voice reference changes.
Hard-contact interpretation and contact-specific qualifications remain available.
This is source-role repair, not a claim that every knowledge entry has received
a substantive astrological or literary review.

`packages/astro-knowledge/review/synastry-source-separation-20261023.json`
records original and updated file hashes, original and retained meaning hashes,
and the hashes of the exact moved units. Git retains the original files. The
knowledge bundle and canonical source index must be rebuilt together.

## Shared request delivery

The shared generator now loads registered directional knowledge sources when
the caller has not selected them. It retains their paths, complete records and
file hashes. A family requires both member sources; unavailable directional
knowledge stops generation. The planner receives selected relationship knowledge
as well as the supplied facts. Previously, knowledge supplied only in the source
snapshot reached the writer but not the planner.

The shared OpenAI and Claude Synastry writers and private body writer load the
complete owner-approved eighteen references in two collections from the existing protected document
store when no explicit complete references were selected. These replace the
automatic adjacent-article selection. The neutral source IDs are
`private:writing/synastry/approved-sample-20261022` and
`private:writing/synastry/approved-ten-20261023` in `PRIVATE_REPORT_DOCUMENTS`.
The envelope is `synastry-approved-voice/v1`; every complete passage retains
its exact text hash and the owner's explicit approval provenance. Missing,
malformed or corrupt default evidence stops before a provider call. Explicit
source selection retains precedence. No source body is committed or added to a
browser bundle.
The repository approval manifests pin all eighteen exact passage hashes. Changing
text and recomputing its storage hash cannot reuse the old prose approval.
Both the generic API function pattern and the generated-content route's explicit
override package `data/writing`, including that text-free approval manifest. The
horoscope packaging regression checks that the explicit route preserves every
source selected by the generic pattern; the initial override omitted this folder.

The body writer's fresh-draft input excludes the old draft's prose, while keeping
the complete original draft and hash in private audit input. Revalidation reloads
protected sources and current feedback from the original request. Changed source,
instruction or feedback hashes hold the request before dispatch.

The Synastry prose instructions retain Ghostwriter craft, effective rules,
ownership, factual and punctuation boundaries, current corrections and the
requested schema. They omit the redundant evaluator specification. Planner and
reviewer roles retain their separate contracts. The full Studio schema and
provider sequence, model defaults, other writing surfaces and publication rules
remain unchanged. The body path remains one call with no retry or model judge.

## Verification and remaining acceptance

Request regressions cover all 732 current directional knowledge records, both
reader roles, complete protected-reference delivery, changed protected-source
hashes, missing/corrupt evidence and the actual shared handler with both providers.
The real Sun–Moon trine and sextile records must reach planning and writing without
their separated advice. Complete author sources remain unchanged.

Provider responses in these regressions are synthetic. Passing them proves
request delivery and boundaries, not Satori voice quality. A live acceptance
check must present the tool's complete untouched output, with its request/source
receipt, rather than a manual chat rewrite. It needs fresh bounded generation
authorization; previous single-call authorization has been consumed. The remaining
bulk entries stay held. No Studio save, publication, default-model change, paid
judge or automatic rewrite is added by this repair.

One separately authorized live GPT-4.1 mini call subsequently completed with
the repaired sources and protected defaults. Its unedited candidate remains
private and unapproved. Agent review found that it still paraphrases generic
knowledge and misapplies a sentence correction. The bulk run and release remain
held. These source fixes do not establish that the writing quality is repaired;
the next model comparison must keep the prepared request fixed to avoid changing
the model and prompt together again. No further provider call is authorized by
that completed one-call test.

One further explicitly authorized GPT-6.1 Sol comparison used the identical
provider request apart from the model. Its complete raw response, token usage,
request equality check and subsequent owner feedback remain in protected storage.
It is a single development case, not evidence that the remaining library is
ready for bulk rewriting or that a default-model change is approved.

The v12 Synastry instruction revision tightens two existing paragraphs: use plain
words for what a person wants or intends to do, develop a supported thought
instead of repeating reassurance, and state an unclear phrase's supported meaning
directly. The exact sentence correction remains private and scoped to its source
entry. This revision adds no vocabulary blacklist, compulsory scene, conflict,
advice ending, provider stage, model change or prose approval. The frozen model
comparison remains unchanged; its result does not evaluate this later revision.

The private merged protected-source payload is prepared separately. Deployment
must provision that payload without replacing existing protected documents,
pass the exact-head PR checks, deploy from main and verify deployed evidence.
A local fixture or prepared payload is not evidence of production provisioning.
