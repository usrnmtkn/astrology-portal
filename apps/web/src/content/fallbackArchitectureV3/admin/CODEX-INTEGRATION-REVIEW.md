# Integration review — app import of the v3 package (2026-07-21)

Reviewed against Codex's status report and dev screenshots (Sky pages: Mercury Rx article, Sun in Cancer placement, Saturn placement).

## Confirmed good

- All five file counts in the app match the package (268 vocab / 909 hooks / 158 source rows / 22 templates / 920 authored cards).
- Package verifiers and `build:web` pass.
- Authored retro card renders verbatim on the Mercury Rx page.

## Must fix (app side)

1. **Remove the local pronoun/grammar "protection" layers from package output.** The report says local friend-name/pronoun fixes and "aspect fallback protections for first-name openings and bad they/them grammar" were kept. The package produces correct grammar by construction (voice parameter, voice-neutral slots). Any post-processor that rewrites pronouns in package output is the bug class documented in DECOMMISSION-OLD-FALLBACKS.md. These layers must never touch package renders. If one ever fires on package output, treat it as a selection bug upstream, not a save.
2. **A legacy fallback path is still live.** "Saturn Quincunx Venus — [FALLBACK] Venus is quincunx Saturn in the sky right now. Watch where love, pleasure, taste, and values and structure, discipline, limits, and time show up in the same conversation, decision, delay, or reaction." This copy is not from the package (quincunx is intentionally uncovered; the grammar is broken). Selection is authored-or-v3-or-SOURCE_GAP. Minor aspects (quincunx, semisextile, etc.) should be omitted from reader surfaces, not routed to an old helper.
3. **Source/glossary text is serving as reader copy.** "Sun Square Chiron — [AUTHORED] ~3 Signs / ~90°; friction that pushes action; uncomfortable but productive..." That is definition material, not a reader card, and it is mislabeled AUTHORED. Sky-page aspect items should render through the package sky event frames (pairEffect). Rows with `content_role: fallback_source` never render.
4. **Derivation data is leaking into reader copy.** "Jul 22, 2026 falls inside the calculated Jun 29, 2026 to Jul 23, 2026 retrograde window." Keep the derivation record in metadata (spec section 8). Pass real dates to the renderer as `window: "Until Jul 23"` and let the copy carry the timing.
5. **Strip `[AUTHORED]` / `[FALLBACK]` tags** from all reader-facing surfaces before release (dev-only flag).
6. **The sky placement fallback is legacy copy.** "Saturn in Aries — [FALLBACK] ...the Saturn theme of structure, discipline, limits, and time is active in a bold, fast, self-starting way... Treat it as weather, not a verdict: name the signal..." is not package output: "weather" is machine-banned vocabulary (CONTENT-ROLE-CONTRACT.json styleRules), and the "conversations, decisions, delays, or reactions" formula is the same legacy helper as item 2. The package intentionally has no generic planet-in-sign sky blurb; where the owner's authored sky placement line exists (it does for Saturn: "Our lesson is patient courage, and reckless starts get corrected for all of us."), render it alone. Where none exists, hide the block (SOURCE_GAP), never route to the old helper. Quick audit: grep reader surfaces for "weather", "name the signal", and "conversations, decisions, delays, or reactions" — any hit is a live legacy path.

7. **The natal Ascendant page is serving legacy copy, not `renderNatalAngle`.** Dev render showed "You come across as quick, curious, and talkative; people meet your mind first." for Ascendant in Gemini. That sentence does not exist in the package (and uses "come across" phrasing the owner rejected). The package render for every angle is a full paragraph from `renderNatalAngle({ angle, sign, voice })` (e.g. Gemini rising: "Your rising sign is the doorway to your chart... Just make sure adapting to everyone does not mean losing yourself along the way."). Route all four angle pages (ASC/MC/DSC/IC) through `renderNatalAngle` and delete the old one-liner helper. Audit grep: "come across", "people meet your mind first".

8. **The You-page transit cards are serving legacy copy, not `renderTransitAspect`.** Dev render: "Right now Saturn is square your natal Venus. This can place structure, discipline, limits, and time in contact with love, pleasure, taste, and values for this window." That frame ("Right now... This can place... for this window") is the old engine-visible template and exists nowhere in the package. The package output for the same transit is the owner's authored card (headline "Loving someone shouldn't feel like a to-do list." + body). Route the transit list through `renderTransitAspect({ transiting, natal, aspect, variant, window })`, passing the real window phrase the app already computes for the date chips (e.g. "Until November 13"). Audit grep: "Right now ", "This can place", "for this window".

9. **Empty-house pages: replace the app helper with `renderNatalEmptyHouse`.** The current app copy has live pronoun-substitution bugs ("the way their daily needs are handled... quietly draining they", "how they thinks, speak") plus grammar slips ("relationship with trust may not follow", "stability starts to matter" with plural subjects). The package now ships `renderNatalEmptyHouse({ house, sign, rulerSign, rulerHouse, ruler?, voice })` in `renderFallback` (mjs + browser, 288/288 parity): returns `note` (the gray explainer) + a four-paragraph body (sign-on-cusp, ruler line, ruler placement via the dual-voice placement sentences, activation close). Ruler defaults to traditional rulership (Pisces -> Jupiter, Aquarius -> Saturn, matching current app behavior); pass `ruler` to override. Rows are `needs_review` and gated. Audit grep: "draining they", "they thinks", "planet to follow here" (the last identifies the legacy helper's frame).

10. **Sky placement pages: wrong renderer for the aspect cards, and the article is truncated.** Dev build (Sun in Cancer): the Gifts/Lessons cards render transit-to-NATAL copy ("You've been dragging and calling yourself lazy..." is the owner's authored Sun-Neptune card about a reader's natal Neptune). Sky pages describe the sky, not a chart: use the new `renderSkyAspectCard({ a, b, aspect, aSign, bSign, dateLine })`, which writes the collective version ("Right now, the Sun in Cancer is trine Neptune, and for everyone at once, ..."). Pass the real `dateLine`/window when known. `renderTransitAspect` output belongs ONLY on the You page and friend charts. Also: the placement article rendered as one squashed paragraph missing the you-voice opener, practice paragraph, element close, and blessing sign-off — render `renderSkyPlacement(...).parts` as separate paragraphs, and pass the `events` array so the aspect paragraphs appear inside the article too.

11. **`readerSafety.ts`: demote the phrase denylist; it is masking live legacy paths.** Codex added runtime pattern checks ("active here", "current emphasis") that reject stale copy so the caller "falls through to the next source." Two problems: (a) the app should never have multiple copy sources per surface — the package resolver is the selection (authored-first internally, metadata-gated, SourceGapError on gaps); if a stale string can reach readerSafety, a legacy generator is still in the path and must be deleted, not filtered; (b) style decisions from sentence text are exactly the text-surgery class this architecture forbids. Target state: render through the package; catch SourceGapError and hide the surface; readerSafety does mechanical sanitation only (empty copy, [FALLBACK]/[AUTHORED] debug tags, markdown junk). Keep the legacy fingerprints, but as a DEV-MODE CANARY that logs an error when one appears in rendered output — an alarm proving the decommission holds, never a gate that hides that it doesn't.

## Supabase / admin import (agreed gap)

`scripts/import-dashboard-source-rows.mjs` still reads legacy JSON paths. Needed: a V3 import path that materializes the package into Supabase for the admin, keyed by `contentKey`.

- Columns: `content_key`, `content_role`, `review_status`, `headline`, `body` / `body_you` / `body_they`, `tag`, `notes`, `source_keys`, `approved_via`.
- Admin buckets: **Authored content** (authoredCards + full_copy), **Fallback system** (templates, hooks, vocabulary), **Source material** (fallback_source — editable/reference-only, never reader-serving).
- Reader-serving queries filter: `content_role != 'fallback_source'` AND `review_status` in (approved, approved_reuse, reviewed).
- The JSON package remains the source of truth; Supabase mirrors it. Re-running the import is idempotent (upsert on `content_key`). After import, verify counts in the dashboard match the five package counts above.
